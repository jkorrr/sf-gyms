# Security policy

This is an early-stage project. Do not include credentials, private user data, or production database exports in issues or pull requests.

For a suspected vulnerability, contact the repository owner privately rather than publishing exploit details. Reproduction steps should omit tokens, OAuth codes, refresh tokens, database URLs, and personal information.

The project treats the following as security-sensitive:

- Supabase service-role keys and database credentials.
- Google OAuth client secrets and authorization codes.
- RLS policies and role-changing functions.
- Owner claims, moderation actions, and audit records.
- User reviews, leads, and account data.
